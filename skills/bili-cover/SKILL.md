# B 站封面制作

结合**视频内容、标题和主播形象**做封面。沿用对话中已确定的文字、皮套、版本和比例，先完成可审阅的首稿；只有缺少会影响结果的信息时才问。封面请求本身不授权投稿或修改已有稿件。

## 1. 选择制作方式

| 用户意图 | 执行方式 |
|---|---|
| 「直接截图」「去掉文字」「第 49 秒当封面」 | 从视频提取清晰原帧，保留原画面和原比例；不自动加字、重绘或加时间码 |
| 「视频截图＋文字」 | 原帧上排用户指定短句，使用普通粗黑体、清楚的对比色；保留视频里的实际人物和场景 |
| 「设计封面」「结合人物形象做」 | 按内容选择表情拼贴或核心道具插画；使用图片生成/编辑工具，见 [生成与改稿](references/generation.md) |
| 「看下封面」「用这张」「换个表情」 | 沿当前封面分支展示、采用或修改，准确对应版本；查看现有封面不自动变成重新生图 |

纯截图只需提帧并查看是否清晰、是否符合指定时刻。截图加字和设计稿先读 [选图、排版与双比例规范](references/style-guide.md)。用户从设计改成「直接截图」时，以最新选择为准。

## 2. 准备素材

- **内容**：查看片段代表帧，必要时回看片段，确认梗、动作、人物关系和核心道具。背景、游戏物品、技能或广告 Logo 优先从视频实际画面取得。保留用户要的品牌图标，选清晰原帧，避免凭印象重画。
- **身份**：使用用户已确认的三视图、皮套图或本场截图；核对脸、发型、衣服、饰品。真人照不能替代用户要求的皮套。人物参考负责身份，视频帧负责场景，风格参考只借布局、配色与字效。
- **文字**：封面主句与投稿标题互补，默认精简为一两行。用户给定封面文案时逐字沿用；仅修改封面文字不顺带修改投稿标题。
- **复用**：有本地素材登记和元数据就先查，避免重复搜索。bili-clip 的登记表为 `~/.config/bili-clip/streamers.json`，人物档案为 `~/.config/bili-clip/streamers/<主播名>.md`；按登记路径找到原图并实际查看。资料缺失时再从直播录像或模型展示视频补充，记录来源，不把未核实的形象当成已确认素材。

独立任务不要求存在 bili-clip、BV 号或候选 JSON。用户给视频、截图和人物参考即可制作。

### 从视频提帧

先辨明时间属于原录播还是剪后成片；拼接视频按编辑记录映射，不能只加一个起点偏移。FFmpeg 精确提取本地视频的指定帧，例如：

```bash
ffmpeg -i "/absolute/path/video.mp4" -ss 00:00:49 -frames:v 1 -update 1 "/absolute/path/cover.png"
```

截图加字可用现有排版工具，或 FFmpeg `drawtext` 配本地字体和 UTF-8 `textfile`；文案通过文件传入，避免中文标点和 shell 转义错误。此方式用于原始截图排版；生成式图片的编辑按 `generation.md` 执行。

## 3. 构图默认值

- **简洁、有梗、大脸大字**：突出一个反应或冲突，一个必要道具；减少抢眼背景、特效和装饰。简洁不等于把人物和字都缩小。姿势自然，头颈、手臂、物品归属清楚。
- **普通粗实心字**：默认高对比中文黑体，一层清晰描边，按语义换行。两行可以用不同颜色区分主次，保留字腔；用户明确要重复文字铺满等特殊效果时按其要求。
- **默认设计稿 4:3，兼容居中裁成 16:9**：核心内容在中间 75% 高度，上下各 12.5% 是可舍弃背景。文字及描边、脸、耳尖/发饰、关键手势和道具留出裁切余量。上下自然延伸背景，不做黑白边。
- **用户指定 16:9 时按指定做**；若同时要求兼容裁成 4:3，关键内容放在中间 75% 宽度，左右各 12.5% 可舍弃。原截图按用户要求使用，不为了套默认比例擅自裁掉内容。
- **适配优先局部调整**：移动文字或道具、调整人像范围，保住主体大小。用户选了第一版就采用第一版，不能擅自换成后出的“安全版”。

这是用户的一图复用偏好，不宣称为 B 站所有展示端的官方安全区。

## 4. 保存与交付

沿用项目目录；bili-clip 用 `<工作目录>/cover-design/<候选 id>/`，独立任务用 `<项目目录>/cover-design/<名称>/`。保存参考图和来源、每版准确文案/提示词、输出文件。已有自动截图和旧版本保留，生成稿不覆盖原图。

用简短 `design-record.json` 记录每版 `version`、`mode`、`output`、`text`、`references`（路径、来源与用途）、`source_time`（时间及原片/成片基准）、`accepted`；按实际素材填写，选中版本单独记录。生成稿另记提示词路径。

制作阶段查看目标比例原图及需要兼容的裁剪图，带字/设计稿再看 320px、160px 宽缩略图：文字正确可读，人物身份与表情可辨，关键内容完整，动作自然。发现问题针对性修改，不把基础制作检查留给用户。已通过的版本在发布时直接复用检查结果。

展示封面、版本和一句设计意图，附实际文件路径。用户明确「用这张」，或在看过封面后说「发布/发吧」，即接受当前版本，不再单独追问封面确认。

### bili-clip 衔接

只有采用后才把对应 `candidates.json` 中的 `cover` 改为该版本绝对路径；原截图继续保留。后续 `cut` 若将 `cover` 写回自动截图，从已确认记录恢复。独立任务无需创建候选 JSON。

用户明确要求发布时，交回 `bili-clip` 的发布分支，复用已确认视频、标题和封面直接上传；本 skill 不增加投稿计划、账号核对或再次确认步骤。只要求封面时交付封面即可。
