# 切片封面的选图、排版与首稿检查

适用：B站主播聊天、游戏与互动切片。设计封面时先读本文件，再写生图提示词。这里是制作建议，不是全站点击率定律。来源：2026-10-31对32个公开视频封面（21位UP主）的目的抽样；有热门、近期和密度对照，没有CTR或随机实验。

## 1. 先定笑点，再选素材路线

用一句话写出“谁遇到什么事、什么反应”。以下三条路线按片段选，不按固定画风选：

| 路线 | 适合内容 | 素材与构图 |
|---|---|---|
| 实况截图＋短句 | 操作失误、机关、Boss、现场证据 | 找能说明事件的一帧；局部压暗文字背后，放大关键物件；需要时加主播表情。背景仍能识别游戏，不必另画场景 |
| 表情/人物拼贴＋对白 | 嘴硬、聊天、双人互动 | 人物表情和说话关系为主；一句反应可放在脸旁，两句对白分别靠近说话人。背景用实际场景、灰化画面或纯色 |
| 核心道具插画 | 原画面未直观展示的事件，如吃烧饼 | 主播身份＋可信表情/动作＋一个关键道具；背景少信息。仅为表达笑点补必要视觉，不补造人物关系 |

“简洁”是减少抢眼中心，**不是缩小全部内容**。脸和道具可以很大；不必每次画全身、完整室内场景或复杂姿势。头像、衣服、发型以用户选定/本场参考为准。

背景选择先看事件、反应、干净画面三类代表帧。相关游戏/聊天证据可以保留并放大，删除无关UI、礼物、日期。不要把无关漂亮背景作为主角。

## 2. 准确短句与字形

- 封面与投稿标题互补。先试约4—10字的主句；这是起稿范围，不是平台限制。双人对白可更长，按说话人分块。
- 先决定准确文字、换行和主次，再做描边。按语义换行：`险遭烧饼 / 单杀！`、`我不是 / 百合！`，不要切断关键词。
- 默认一到两级文字；副信息没读到也应看懂主梗。主播名多数由皮套和投稿标题承担。
- 强调色服务语义或数字。例如“六十万”最大、“下播”变黄；不要每个字等大等亮，也不要机械逐行换色。
- 少字/无字适合画面已说明事件的片段，不是所有切片的默认。长标题直接压进封面通常不是精简。

字体观察与字体指定分开：从位图只判断粗黑、窄斜、圆润、描边等风格；没有作者说明，不报出确切字体名。图像模型也不能保证真实调用某个字体。

可选实际字库：
- [思源黑体SC](https://github.com/adobe-fonts/source-han-sans)：Bold/Heavy作中性主力；不是圆体。
- [得意黑](https://github.com/atelier-anchor/smiley-sans)：短标题的窄斜动势；用户要求普通黑体时不用它代替。
- [Google Fonts发行版站酷快乐体](https://github.com/google/fonts/tree/main/ofl/zcoolkuaile)：活泼展示字候选，不默认用于所有文案。

这些指定来源采用OFL；作品与分发字体文件是不同授权对象。字体文件从发布方取得并保留对应许可版本，不从字体外观或聚合站标签推断授权。生图提示词只描述字形风格；需要精确字库时使用实际字体排版工程。已生成封面的错字仍按`cover-design.md`返工，不用代码涂改。

## 3. 配色与字效

优先明度对比，再选强调色。深画面可用白/黄字，浅背景用深字或明显深描边。以下HEX是建议值，不冒充样本原工程色号：

| 用途 | 主字/强调 | 深描边 | 背景 |
|---|---|---|---|
| 游戏搞笑 | 暖白`#FFF8EE`＋黄`#FFE33B` | `#17151C` | 实况原色，字后局部压暗 |
| 轻松聊天 | 深紫黑`#231C2D`或暖白＋粉`#FF7698` | 依据背景反差选深/浅 | 米白、浅灰、简化场景 |
| 双人对白 | 白字＋一个黄关键词；必要时浅蓝/浅粉区分发言 | 近黑 | 暗场景或纯色，人物保留原色 |
| 动作高能 | 白/黄＋一种事件色，如橙`#FF9248` | 近黑 | 按实际事件选，不因紫发就全图紫色 |

默认粗实心字、一层深描边，必要时细亮边/轻阴影。白外边、紫厚边、粉发光不默认全叠。字腔闭塞时先减边/减背景复杂度，而不是继续加效果。人物细白边可分离暗背景；特效只在电流、挑战等真实题材需要时用。

## 4. 构图与双比例

2026-10-31当前账号网页封面制作器直接标注：首页推荐4:3、个人空间16:9，提供“双比例同步改动”。这是当时该界面观察，不保证所有展示端相同。2018视频封面像素建议、2021直播封面尺寸不能冒充现行视频投稿规则；当前上传限制以实际界面为准。

保持用户默认：4:3稿兼容居中16:9。数学上，中间75%高度会留下，上下各12.5%可裁；这是一图复用方法，不是平台给出的全端安全区。

先设计中央16:9核心，再让4:3上下自然延伸低信息背景。所有字及描边、脸、耳尖/发饰、手和关键道具留在核心带内，并留余量。不要先画满4:3，出问题后把人物和字整组缩成小岛。

适配失败时，优先移动文字、调整人像局部范围/道具位置，保住大脸、大字。确有需要可分别构图；网页编辑器支持查看两种比例，不等于现有`biliup --cover`已支持独立上传两张，发布路径需另核实。

1600×1200稿的可调起点：
- 16:9核心带y=150—1050；重要边缘再向内约30—50px。
- 左右约80—110px呼吸空间；随版式调整。
- 主字高约120—180px，左侧两行常每行3—5字；副信息为主字的45%—60%。
- 深描边约字高4%—7%；行距约字高1.08—1.18倍，包含外扩边。

这些数值是内部起点，实际以小图可读、身份和道具关系完整为准，不作为僵硬网格。还要模拟卡片底部播放/弹幕、右下时长遮挡；各端位置可能不同。

## 5. 交付首稿前

1. 保存人物身份图和代表帧；选一条素材路线、两张结构相近的参考，写一句原因。参考只借信息层级和布局，不复制对方资产。
2. 检查准确文案、换行、说话人、动作和道具归属。用户已给定的皮套/比例/普通字体偏好直接沿用。
3. 按`cover-design.md`记录提示词并生成。常规请求先完成可审阅首稿，不重复为已有偏好询问六个维度；用户明确先选方向或否定了整体风格时，再给2—3个差异明显的方向。
4. 并排看4:3、16:9、320px与160px宽缩略图；模拟底部叠层。能认出主角、读出主句、看出表情与物件，才值得展示。
5. 文字错、身份漂移、头颈手势扭曲、关键内容被裁，先自行针对一个主问题返工；不要让用户替我们做基础QA。
6. 展示版本号和简短设计意图；记录具体采用/否决理由。用户选第一版时准确映射到第一版，不自动用后出的“安全版”。采用和发布仍按`cover-design.md`的授权边界执行。
