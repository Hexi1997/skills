# 切片封面设计

这是按需分支。用户明确要设计、生成或重做封面时才执行；普通 `cut`、查看自动封面、选择 `cover_at` 都停留在截图流程。进入设计分支后，「看下封面」「换个风格」「用这张」等后续短句继续指向当前设计稿，不退回自动截图流程。

## 工具与默认值

- **REQUIRED SUB-SKILL:** 使用 `baoyu-cover-image` 完成封面设计、确认和提示词记录。
- **REQUIRED SUB-SKILL:** 使用 `imagegen` 生成或编辑位图；若当前运行时没有可用的图片生成工具，说明限制并停止，不用 SVG、HTML 或程序绘图替代。
- 默认生成比例：**4:3**，构图必须同时兼容居中裁成 **16:9**，遵循下方安全区规则。用户明确指定其他比例时按用户要求；要求多个独立设计版本时分别构图、生成。
- 默认输出目录：`<工作目录>/cover-design/<候选 id>/`。提示词放 `prompts/`，参考图放 `refs/`，成品复制到 `clips/<视频文件 stem>_设计封面_<比例>.png`。

### 内容与简洁度

- 封面结合**视频标题、主播形象、片段实际内容**设计：标题确定要表达的梗，人物参考锁定主播身份，视频画面确定场景、动作和关键道具。标题尚未确定时从片段内容提炼简短封面文字，不补造视频里没有的情节。
- 生成前查看片段的代表画面；需要表现游戏、环境或技能时，保存实际截图作为场景参考。不能只根据字幕关键词设计一个脱离视频的通用背景。
- 默认简洁，突出人物、简短标题和支撑笑点的核心视觉元素；背景简化、弱化细节，保留留白和清楚的视觉层次。控制字数、配色与特效密度，不堆砌装饰、碎石、光线、粒子或多个抢眼元素。
- 在缩略图尺寸下，主播身份、标题和内容关联仍应一眼可辨；若装饰抢过人物或标题，先删减装饰，而不是继续加光效、描边或文字。

### 4:3 与 16:9 共用构图

- 同宽的 4:3 图居中裁成 16:9 后，只保留原图中间 **75% 高度**（纵向 12.5%–87.5%），上下各裁掉 **12.5%**。例如 1536×1152 的图保留中间 1536×864，上下各去掉 144 像素。
- 所有文字及描边、人物脸与身份辨识饰品、关键手势和道具、表达内容的核心场景元素都放在这个安全区内，并与裁切边界留出余量。裁切后人物身份、动作、笑点和标题仍须完整、清楚。
- 上下两段只放低信息量、可舍弃的背景，如天空、渐变、地面或稀疏环境延伸；不要放文字、重要饰品或叙事线索。它们是自然画面的延伸，不是黑边、白边，也不要画出安全区辅助线。
- 默认只生成一张符合上述要求的 4:3 原图；兼容 16:9 指裁切安全，不需要另生成一个版本。用户明确要求导出 16:9 时，可从该原图居中裁切。

## 1. 准备参考图

把参考图的职责分开，并在提示词中标明每张图的作用：

1. **人物身份图**：优先用用户选定的时间点；否则用 `cut` 生成的同名 `.jpg`。它负责角色的脸、发型、服装、饰品和表情。
2. **场景内容图**：来自所剪片段的实际截图，负责环境、动作、关键道具和技能表现；可简化为适合封面的插画，但保留与视频内容的联系。
3. **风格参考图**：用户说「参考这张的风格」时使用，负责版式、配色、字效、光影和装饰密度，不复制其中人物、标题或专属元素。

先用图片查看工具检查每张本地参考图。人物图排在第一张，其后是场景图（需要表现具体场景时）和风格图（用户提供时）。直播 UI、评论区、弹幕、Logo、时钟和日期默认从设计稿中移除，除非用户要求保留。

## 2. 确认设计

生成前用一段简短设计说明让用户确认：

- 比例（未指定时生成 4:3，并兼容居中裁成 16:9）
- 封面上的准确文字
- 人物位置和标题位置
- 背景主题、色彩和字效
- 哪张图锁定人物，哪张图参考实际场景，哪张图只参考风格

用户说「直接生成」「不用确认」或已经逐项确认时，按 `baoyu-cover-image` 的快速流程继续。用户只是否定当前风格时，先给 2–3 个明显不同的方向并等其选择，不连续盲抽。

## 3. 生成与保存

每张图在调用图片生成工具前，先把完整最终提示词保存到 `prompts/NN-<slug>-<比例>.md`。提示词至少包含：

- 用途：B 站切片缩略图
- 人物身份的不变量
- 标题所表达的梗、视频实际场景与关键动作，以及简化背景、控制装饰和光效密度的要求
- 风格参考中要继承的版式特征
- 严格的目标比例和左右构图
- 默认 4:3 时，明确中间 75% 高度为 16:9 安全区，上下各 12.5% 只放可舍弃背景，并列出必须完整保留在安全区内的文字、人物与场景元素
- 可见文字的逐字内容与换行方式
- 只允许出现的角色数量
- 必须移除的直播覆盖层和禁止出现的额外文字

调用原生图片生成工具时传入人物身份图，以及本次采用的场景内容图、风格参考图。生成后把工具输出从其默认目录复制到本分支的输出路径；保留原始自动封面和未采用的候选，不覆盖同名 `.jpg`。

## 4. 验收与返工

展示成品前逐项检查：

- 文件存在且目标比例正确；4:3 允许生成器的轻微像素取整误差
- 默认 4:3 图须查看居中裁成 16:9 的预览，确认上下各去掉 12.5% 后，文字及描边、脸与身份辨识饰品、关键动作和道具、核心场景元素均完整，主题和视觉重心仍成立；仅在 4:3 原图里完整不算通过
- 人物身份、发型、服装和关键饰品可辨认
- 场景、动作与道具贴合所剪视频，标题和人物形成明确的内容关联；缩略图尺寸下人物与标题清楚，背景和装饰不抢视觉重心
- 标题逐字正确，小尺寸下仍清楚
- 版式确实继承风格参考，而不是复制参考图的人物或文字
- 没有直播 UI、评论、Logo、时钟、水印和意外的额外人物

文字错误、乱码、身份明显漂移或关键内容超出 16:9 安全区时，写新的提示词文件并重新生成；保留旧候选用于对比。可以用图片工具做居中裁切预览以验收安全区，但不要通过缩放后补边或搬移文字来补救构图，也不要在生成图上用 Pillow、ImageMagick、Canvas、SVG 或 HTML 覆盖、擦除、修补标题。

## 5. 采用与发布衔接

先把设计稿展示给用户。此时只报告候选路径，不改 `candidates.json` 里的 `cover`。

用户明确说「用这张」「就这个封面」后，才把对应候选的 `cover` 更新为已确认设计稿的绝对路径。自动截图继续保留在原处。之后 `publish` 的投稿计划会读取这个 `cover`；仍然先运行不带 `--yes` 的发布计划，用户明确回复「发」后才能真正上传。

如果用户后来重新运行 `cut`，脚本可能把 `cover` 写回自动截图路径；发布前重新核对 `candidates.json` 指向的是否仍是已确认设计稿。
