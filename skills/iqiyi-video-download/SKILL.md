# 爱奇艺分集视频下载

交付指定剧集的本地 MP4，证明集号对应正确、视频和音频可完整解码。网页能播放、HTTP 200 或 ffprobe 能读出时长，都不能单独证明下载成功。

## 范围

- 下载授权只覆盖本地文件。替换线上素材、上传、发起分析、付费调用是后续动作，须有用户明确授权。
- 使用正常可访问的播放资源，不破解 DRM、提取解密密钥、猜密钥或绕过付费限制。若拿到的仍是密文，说明阻塞原因。
- 不把账号 Cookie、登录令牌、临时签名 URL 或实际业务 ID 写进 skill、Git 或最终答复。

## 工作流

### 1. 确认作品和集号

核对标题、季数、总集数与简介。重名剧、不同季和不同剪辑版不能只凭标题认定相同。

保存本地映射：用户集号（从 1 开始）、页面选中集号、媒体 tvid、预期时长、输出路径。若另有业务系统的 0-based chunkIndex，单独记录，不能混用。

### 2. 选择下载路径

若已有 yt-dlp，可先对精确播放页做一次元数据探测：

```bash
yt-dlp --skip-download --dump-single-json --no-warnings --socket-timeout 12 --retries 0 '实际播放页 URL'
```

识别成功且分集身份正确时，使用其正常下载能力。若报 `Can't find any video`，只能说明本次提取失败，不能据此断定视频不可下载，不要反复重试相同提取器。

改用浏览器实际播放请求时，读 [references/browser-network.md](references/browser-network.md)。浏览器工具名称、方法和能力以本次返回的文档为准；没有网络调试能力时，不私自改用未授权的浏览器控制通道。

### 3. 下载真实媒体

- 用选集控件切到指定集，核对页面集号与时长。直达播放 URL 在新版页面中可能仍播放第 1 集。
- 对照当前集的 tvid，读取实际播放请求。播放器会预加载后续集，也可能为同一集请求多个 CDN，不能把第一个 TS 请求直接当目标集。
- 分清媒体清单、CDN 调度 JSON 与实际视频字节；返回 JSON 的 `.ts` 地址不能作为 TS 文件直接封装。
- 下载本次正常播放实际使用的地址；临时签名失效时重新播放获取，不拼接或伪造签名。保留证书校验；若 Python CA 配置失败而系统 curl 正常，可换用 curl。
- 用私有临时目录保存调度回包与签名 URL，报告只保留集号、时长、大小、哈希和验证结论。

### 4. 封装和验证

拿到完整 TS 或其他 FFmpeg 可识别的本地输入后，运行：

```bash
python3 scripts/remux_verify.py --input /absolute/path/episode.ts --output /absolute/path/episode.mp4
```

脚本检查视频、音频、尺寸和时长，以 `-c copy -movflags +faststart` 封装 MP4，再用 FFmpeg `-xerror` 完整解码。通过后输出 SHA-256、大小和元数据，并保存一张中间帧供目视检查。默认不覆盖现有文件。

若时长与页面不符，检查是否抓错集、只下载首片或拿到预加载视频。真正多分片 HLS 按清单顺序合并，不把单个分片当整集。

若出现 `Encryption info`、CENC 标记或大量解码错误，不通过改扩展名、裸 remux、忽略错误转码来宣称修复。清单 `drmType` 也不能单独替代载荷验证：正常播放取得的 TS 可能能直接解码，必须实测。

### 5. 交付

核对抽帧画面与对应剧集，给本地文件链接。批量任务逐集列出时长和通过/失败情况，区分“已下载”“已验证”“已上传”“已替换”“已重新分析”。未执行的后续动作不要暗示已完成。仅下载时关闭临时浏览器页，不自动修改生产系统。
